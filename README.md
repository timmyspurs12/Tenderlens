# TenderLens

TenderLens is a source-first procurement intelligence workspace. It presents amendment review, requirement assessment, and evaluation lifecycle as evidence-dependent work: data absent from the connected backend is explicitly unavailable rather than simulated.

## Run locally

- Node.js 22.14.0 (the version used by the checked-in Dev Container and Direct Mode CI job)
- `npm ci` (uses the checked-in `package-lock.json`; avoid `npm install` when reproducing the locked frontend tree)
- Set `VITE_API_BASE_URL` to the backend origin (for example, `https://api.example.test`).
- `npm run dev`
- `npm run build`, `npm run typecheck`, `npm test`, and `npm run lint`

Never put private credentials, signing keys, or privileged API tokens in `VITE_*` variables. This is a Vite SPA and does not provide server-side authentication or authorization; deploy behind an authenticated backend or identity-aware gateway before exposing tender records.

## Backend

A small standard-library API and SQLite/content-addressed document store is implemented under `backend/`. It supports authenticated tender registration, immutable uploads, server-calculated SHA-256, explicit document links/amendment annotations, requirement registration, and byte-range evidence provenance for plain-text files. `POST /api/tenders/{id}/evaluation-snapshots` freezes all current registered requirements and explicitly selected evidence versions into an immutable, hashed contract submission payload. The hash uses sorted compact UTF-8 JSON (with non-ASCII characters preserved) before adding the digest field; see [`docs/api-contracts.md`](docs/api-contracts.md) for the exact rules and trust boundary. The contract checks digest shape only; it does not recompute or authenticate the hash. That endpoint prepares input only; it does not deploy or invoke a contract. The API requires a workspace-scoped bearer credential; the browser must never receive that privileged token. Therefore the current SPA is not yet connected directly: deploy a same-origin authenticated BFF/identity-aware gateway before wiring protected records into browser views.

Set `TENDERLENS_API_TOKEN` to a random secret of at least 32 characters, `TENDERLENS_WORKSPACE` to the isolated workspace identifier, and optionally `TENDERLENS_DB_PATH` / `TENDERLENS_BLOB_DIR` (defaults under `./var/`). Set a separate stable `TENDERLENS_SNAPSHOT_HMAC_KEY` (at least 32 characters) for snapshot-row authentication; when unset, the API token is used. Keep the HMAC key stable across restarts. Run `python backend/app.py` for local development only; the built-in WSGI server is not suitable for production. Use TLS, an authenticated gateway, and durable encrypted storage for deployments. Snapshot GET routes now recompute the canonical digest and verify an internal HMAC before returning stored snapshots; these are backend checks, not contract-side authentication. Endpoint schemas, error codes, and the distinction between snapshot preparation and network transaction lifecycle are documented in [`docs/api-contracts.md`](docs/api-contracts.md).

The procurement Intelligent Contract accepts a configurable aggregation policy: the default `mandatory_gate_optional_advisory_v1` distinguishes mandatory non-compliance from optional non-compliance, while `all_requirements_blocking_v1` treats either as blocking. Insufficient and contradictory findings remain unresolved under both policies. These are evaluation policies, not award rules. Model citations use structured evidence IDs, and result references are sourced from the submitted snapshot.

The procurement Intelligent Contract is under `tests/genlayer_direct/contracts/procurement_evaluation.py` and is exercised in the pinned Direct Mode runner. `backend.evaluation_adapter.EvaluationAdapter` verifies stored snapshots and manages a durable submission/result ledger; `backend.genlayer_sdk_driver.GenLayerSDKDriver` implements the pinned SDK call path. A server-side API route for submitting a snapshot and querying request status is implemented, but it is **disabled by default**: it requires both an explicitly injected server-side submitter and the server-only `TENDERLENS_GENLAYER_BROADCAST_AUTHORIZED=1` setting. A request field cannot enable broadcast. The standard app factory injects no submitter. The contract now uses the immutable `py-genlayer:1jb45aa8ynh2a9c9xn3b7qqh8sm5q93hwfp7jqmwsfhh8jpz09h6` reference shown in [official GenLayer contract documentation](https://github.com/genlayerlabs/genlayer-docs/blob/7c3ad7c4bc738a7c55d05df780dd76c2cb052db6/pages/developers/intelligent-contracts/first-contract.mdx); this pins a runtime identifier but does not establish that the artifact is available or compatible with any selected target. Missing target-identity, target-runtime qualification, and target-specific funding verifiers keep the driver fail-closed. Read-only recovery requires a target-identity verifier but no signer account. No live network was used. The contract remains independently callable and does not authenticate backend snapshots. This is not a deployed contract or production-ready lifecycle service, and the frontend evaluation flow is unchanged. Direct Mode mocks nondeterministic LLM responses; it does not establish actual model accuracy, deployed validator consensus, or GenVM/WASM compatibility. Amendment annotations remain user-provided and semantic amendment comparison is unavailable. PDFs and DOCX passage extraction are not supported. No demo records are generated.

`VITE_API_BASE_URL` is the frontend's optional service origin. No private key or privileged API token belongs in a `VITE_*` variable.

## GenLayer development container

The checked-in `.devcontainer/Dockerfile` uses the published Microsoft Python image `mcr.microsoft.com/devcontainers/python:3.12-bookworm`. `.devcontainer/setup.sh` checks Python, GenLayer dependency/source pins, uv, Node, and `gltest`; GitHub Actions runs this setup on an Ubuntu-hosted runner, so Codespaces are not required for runtime validation. To reproduce the locked environment locally, install Python 3.12, Node 22.14.0, and uv 0.13.3, then run `bash .devcontainer/setup.sh --genlayer-only`.

The project Python environment is isolated in `.venv`. `requirements-genlayer.lock.txt` locks the resolved runtime dependency graph with hashes, while `requirements-genlayer.in` pins the intended roots. The official suite's PEP 517 backend is constrained separately in `requirements-genlayer-build.lock.txt`. Rebuild the locks with `uv pip compile requirements-genlayer.in --python-version 3.12 --generate-hashes --output-file requirements-genlayer.lock.txt` and `uv pip compile requirements-genlayer-build.in --python-version 3.12 --generate-hashes --output-file requirements-genlayer-build.lock.txt`; install with `uv venv --seed --python 3.12 .venv && uv pip sync --build-constraints requirements-genlayer-build.lock.txt --python .venv/bin/python requirements-genlayer.lock.txt`.

**Important upstream compatibility discrepancy:** the official `genlayer-test` GitHub source at signed commit `343e3a358f9e235a93b49c60721ce7676585ff07` declares version 0.29.2 and `genlayer-py>=0.18.0,<0.20.0`. The PyPI wheel also reports 0.29.2 but its published metadata instead requires `genlayer-py>=0.13.0,<0.17.0`. Those constraints cannot be installed together with SDK 0.18.0. To satisfy the requested compatible pair without overriding dependency metadata, this environment pins the official upstream source commit (package version 0.29.2) and SDK 0.18.0; it deliberately does not install the incompatible PyPI wheel. Both alternatives must be rechecked upstream before changing these pins.

The GenLayer Actions workflow is configured to install and verify the pinned Direct Mode test environment and source commit. A workflow configuration is not a current job result; check the actual run separately before relying on it. Run the Direct Mode contract suite with `.venv/bin/python -m pytest tests/genlayer_direct -v`; it tests deterministic request validation and result assembly plus Intelligent Contract interpretation over the supplied evidence. Direct Mode's `mock_llm` supplies nondeterministic model responses, as required by the pinned runner; this exercises actual contract code/state but is not real model inference or deployed consensus. The contract has not been deployed.

Run `python scripts/genlayer_preflight.py` for the offline, structured deployment-qualification report. It does not make network/RPC requests, invoke an SDK client, or perform wallet, signing, funding, deployment, or transaction operations; `--probe-rpc` is not available. Readiness remains false while any mandatory check is blocked, unknown, or requires user action. See [`docs/genlayer-milestone7-qualification.md`](docs/genlayer-milestone7-qualification.md) for the blocker matrix and the distinctions among ordinary Python tests, Direct Mode, SDK inspection, artifact compilation, and live deployment. The current workflow covers typecheck, frontend tests, build, lint, backend/adapter/preflight tests, locked-environment checks, and Direct Mode. See [`docs/genlayer-milestone4-integrity.md`](docs/genlayer-milestone4-integrity.md) for the snapshot trust audit, [`docs/genlayer-milestone5-adapter.md`](docs/genlayer-milestone5-adapter.md) for application binding/runtime findings, and [`docs/genlayer-milestone6-sdk-driver.md`](docs/genlayer-milestone6-sdk-driver.md) for the SDK surface, driver gates, durable transitions, and recovery limits.

## Design system

Shared colors, type roles, and component patterns are centralized in `src/style.css`: warm porcelain canvas, ink text, restrained forest/amber/red semantic colors, 8px-oriented spacing, DM Sans UI, Newsreader editorial headings, and DM Mono metadata. Breakpoints cover tablet/mobile; reduced-motion and print styles are included.
