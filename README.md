# TenderLens

TenderLens is a source-first procurement intelligence workspace. It presents amendment review, requirement assessment, and evaluation lifecycle as evidence-dependent work: data absent from the connected backend is explicitly unavailable rather than simulated.

## Run locally

- Node.js 22.14.0 (the version used by the checked-in Dev Container and Direct Mode CI job)
- `npm ci` (uses the checked-in `package-lock.json`; avoid `npm install` when reproducing the locked frontend tree)
- For local UI-only work, `VITE_API_BASE_URL` may be unset; the workspace reports the records connection as unconfigured. Production builds default to the same-origin Vercel BFF. For a separately hosted, authenticated gateway, set `VITE_API_BASE_URL` to its public origin (no trailing slash).
- `npm run dev`
- `npm run build`, `npm run typecheck`, `npm test`, and `npm run lint`

Never put private credentials, signing keys, or privileged API tokens in `VITE_*` variables. This is a Vite SPA and does not provide server-side authentication or authorization; deploy behind an authenticated backend or identity-aware gateway before exposing tender records.

## Backend

A small standard-library API and SQLite/content-addressed document store is implemented under `backend/`. It supports authenticated tender registration, immutable uploads, server-calculated SHA-256, explicit document links/amendment annotations, requirement registration, and byte-range evidence provenance for plain-text files. `POST /api/tenders/{id}/evaluation-snapshots` freezes all current registered requirements and explicitly selected evidence versions into an immutable, hashed contract submission payload. The hash uses sorted compact UTF-8 JSON (with non-ASCII characters preserved) before adding the digest field; see [`docs/api-contracts.md`](docs/api-contracts.md) for the exact rules and trust boundary. The contract checks digest shape only; it does not recompute or authenticate the hash. That endpoint prepares input only; it does not deploy or invoke a contract. The API requires a workspace-scoped bearer credential; the browser must never receive that privileged token. `api/[...path].js` implements a same-origin Vercel gateway with an owner passphrase session, server-side token injection, exact-origin write checks, and a fixed upstream URL. It proxies only tender and evaluation-request API paths. This is a single-workspace owner gate, not multi-user identity or per-user membership; use a dedicated strong random passphrase and session key, and do not treat this MVP as enterprise authentication. Do not point the browser directly at the privileged API and never set `TENDERLENS_API_TOKEN` as a Vite variable. Configure the Vercel server-side variables described in `docs/tender-records-data-flow.md` before relying on workspace access. See [`docs/tender-records-data-flow.md`](docs/tender-records-data-flow.md) for the flow, deployment findings, and required setup.

Set `TENDERLENS_API_TOKEN` to a random secret of at least 32 characters, `TENDERLENS_WORKSPACE` to the isolated workspace identifier, and optionally `TENDERLENS_DB_PATH` / `TENDERLENS_BLOB_DIR` (defaults under `./var/`). Set a separate stable `TENDERLENS_SNAPSHOT_HMAC_KEY` (at least 32 characters) for snapshot-row authentication; when unset, the API token is used. Keep the HMAC key stable across restarts. Run `python backend/app.py` for local development only; the built-in WSGI server is not suitable for production. The root `requirements.txt` pins Gunicorn for the backend deployment: use `pip install -r requirements.txt` as the build command and `gunicorn --workers 1 --bind 0.0.0.0:$PORT 'backend.app:create_app()'` as the start command. This only supplies the WSGI server; it does not make filesystem storage durable. The Vercel gateway needs separate server-only configuration and does not change Render's storage durability. Use TLS and durable encrypted storage before keeping real records. Snapshot GET routes now recompute the canonical digest and verify an internal HMAC before returning stored snapshots; these are backend checks, not contract-side authentication. Endpoint schemas, error codes, and the distinction between snapshot preparation and network transaction lifecycle are documented in [`docs/api-contracts.md`](docs/api-contracts.md).

The procurement Intelligent Contract accepts a configurable aggregation policy: the default `mandatory_gate_optional_advisory_v1` distinguishes mandatory non-compliance from optional non-compliance, while `all_requirements_blocking_v1` treats either as blocking. Insufficient and contradictory findings remain unresolved under both policies. These are evaluation policies, not award rules. Model citations use structured evidence IDs, and result references are sourced from the submitted snapshot.

The procurement Intelligent Contract is under `tests/genlayer_direct/contracts/procurement_evaluation.py` and is exercised in the pinned Direct Mode runner. `backend.evaluation_adapter.EvaluationAdapter` verifies stored snapshots and manages a durable submission/result ledger; `backend.genlayer_sdk_driver.GenLayerSDKDriver` implements the pinned SDK call path. A server-side API route for submitting a snapshot and querying request status is implemented, but it is **disabled by default**: it requires both an explicitly injected server-side submitter and the server-only `TENDERLENS_GENLAYER_BROADCAST_AUTHORIZED=1` setting. A request field cannot enable broadcast. The standard app factory injects no submitter. The contract pins `py-genlayer:1jb45aa8ynh2a9c9xn3b7qqh8sm5q93hwfp7jqmwsfhh8jpz09h6`, the exact content-addressed runtime reference in the [official GenLayer contract documentation](https://github.com/genlayerlabs/genlayer-docs/blob/7c3ad7c4bc738a7c55d05df780dd76c2cb052db6/pages/developers/intelligent-contracts/first-contract.mdx). The Direct Mode environment is pinned to official Testing Suite v0.30.0-rc.2 source and genlayer-py v0.19.0-rc.2 to support current GenVM bundle formats. Neither a documented hash nor Direct Mode success establishes compatibility with a selected live network or validator runtime. Missing target-identity, target-runtime qualification, and target-specific funding verifiers keep the driver fail-closed. Read-only recovery requires a target-identity verifier but no signer account. No live network was used. The contract remains independently callable and does not authenticate backend snapshots. This is not a deployed contract or production-ready lifecycle service, and the frontend evaluation flow is unchanged. Direct Mode mocks nondeterministic LLM responses; it does not establish actual model accuracy, deployed validator consensus, or GenVM/WASM compatibility. Amendment annotations remain user-provided and semantic amendment comparison is unavailable. PDFs and DOCX passage extraction are not supported. No demo records are generated.

`VITE_API_BASE_URL` is a public build-time origin for the authenticated user-facing gateway only; it is not the privileged API credential. Configure it only after an appropriate gateway exists. No private key or privileged API token belongs in a `VITE_*` variable.

## GenLayer development container

The checked-in `.devcontainer/Dockerfile` uses the published Microsoft Python image `mcr.microsoft.com/devcontainers/python:3.12-bookworm`. `.devcontainer/setup.sh` checks Python, GenLayer dependency/source pins, uv, Node, and `gltest`; GitHub Actions runs this setup on an Ubuntu-hosted runner, so Codespaces are not required for runtime validation. To reproduce the locked environment locally, install Python 3.12, Node 22.14.0, and uv 0.13.3, then run `bash .devcontainer/setup.sh --genlayer-only`.

The project Python environment is isolated in `.venv`. `requirements-genlayer.lock.txt` locks the resolved runtime dependency graph with hashes, while `requirements-genlayer.in` pins the intended roots. The official suite's PEP 517 backend is constrained separately in `requirements-genlayer-build.lock.txt`. Rebuild the locks with `uv pip compile requirements-genlayer.in --python-version 3.12 --generate-hashes --output-file requirements-genlayer.lock.txt` and `uv pip compile requirements-genlayer-build.in --python-version 3.12 --generate-hashes --output-file requirements-genlayer-build.lock.txt`; install with `uv venv --seed --python 3.12 .venv && uv pip sync --build-constraints requirements-genlayer-build.lock.txt --python .venv/bin/python requirements-genlayer.lock.txt`.

**GenLayer test-toolchain pin:** the official Testing Suite v0.30.0-rc.2 source at commit `d84591b58746a6202b56b720199ce7b9f12fd666` declares `genlayer-py>=0.19.0rc2,<0.20.0`. This repository pins that release commit, `genlayer-py==0.19.0rc2`, and `pytest==9.1.1` in hashed locks. This is an official prerelease toolchain; deployment still requires independent target-runtime qualification. Do not silently substitute mutable branches or incompatible wheels.

The GenLayer Actions workflow installs and verifies the pinned Direct Mode environment. Earlier runs failed while injecting the Direct Mode message and when storage expected `__type_desc__` metadata. Current CI run 39603920699 passes the Direct Mode suite using the pinned runner. This verifies test execution against Direct Mode with mocked nondeterministic responses; it does not establish real model inference, target GenVM/WASM compatibility, deployed consensus, or a live transaction. The contract has not been deployed.

Run `python scripts/genlayer_preflight.py` for the offline, structured deployment-qualification report. It does not make network/RPC requests, invoke an SDK client, or perform wallet, signing, funding, deployment, or transaction operations; `--probe-rpc` is not available. Readiness remains false while any mandatory check is blocked, unknown, or requires user action. See [`docs/genlayer-milestone7-qualification.md`](docs/genlayer-milestone7-qualification.md) for the blocker matrix and the distinctions among ordinary Python tests, Direct Mode, SDK inspection, artifact compilation, and live deployment. The current workflow covers typecheck, frontend tests, build, lint, backend/adapter/preflight tests, locked-environment checks, and Direct Mode. See [`docs/genlayer-milestone4-integrity.md`](docs/genlayer-milestone4-integrity.md) for the snapshot trust audit, [`docs/genlayer-milestone5-adapter.md`](docs/genlayer-milestone5-adapter.md) for application binding/runtime findings, and [`docs/genlayer-milestone6-sdk-driver.md`](docs/genlayer-milestone6-sdk-driver.md) for the SDK surface, driver gates, durable transitions, and recovery limits.

## Design system

Shared colors, type roles, and component patterns are centralized in `src/style.css`: warm porcelain canvas, ink text, restrained forest/amber/red semantic colors, 8px-oriented spacing, DM Sans UI, Newsreader editorial headings, and DM Mono metadata. Breakpoints cover tablet/mobile; reduced-motion and print styles are included.
