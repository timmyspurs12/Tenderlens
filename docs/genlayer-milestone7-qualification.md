# Milestone 7 — read-only deployment qualification

## Decision and operating boundary

The Milestone 7 qualification command is `python scripts/genlayer_preflight.py`. It is an offline, local-only report, not a deploy command. It prints JSON using schema `tenderlens.deployment-qualification.v1`; exits `0` only when every mandatory check is `verified`, and exits `2` otherwise. Every check carries a stable ID, one of `verified`, `blocked`, `unknown`, or `requires_user_action`, explanation, local evidence, safe resolution, owner, whether an operator/maintainer must act, and whether resolution would require external interaction or a side effect.

The command reads local project files, Python package metadata, interpreter version, and selected environment-variable presence/shape. It does not print variable values, query RPC, make HTTP requests, instantiate the SDK or driver, pull images, install packages, create/import/unlock/fund wallets, sign, deploy, submit transactions, or poll a remote service. `--probe-rpc` is intentionally not an option. Its `external_side_effects_performed` field is always empty because preflight itself does not take external actions. A declared resolution requiring an external interaction is a blocker description, not authorization to perform that interaction.

The output distinguishes a check being locally verified from deployment readiness. For example, finding an environment value with the expected private-key text shape does not verify key ownership, target authorization, account derivation, or balance. Finding a driver callback gate does not mean a verifier is implemented or its result is trustworthy. Network-name and endpoint-string matches do not authenticate a remote chain. A content-looking digest or a tag other than a known mutable alias is not treated as authenticated or compatible evidence.

## Current official network facts and selection boundary

The official GenLayer docs at revision `7c3ad7c4bc738a7c55d05df780dd76c2cb052db6` list Bradbury as a production-like testnet, but distinguish the **GenLayer RPC** used for intelligent-contract methods from the underlying GenLayer Chain/L2 RPC. The docs say to use the Phase 2 node RPC from the release announcement (or an independently qualified node) for intelligent-contract operations; the public `rpc.testnet-chain.genlayer.com` endpoint is the underlying chain RPC and is not by itself a valid GenLayer SDK deployment target. The same docs warn that Bradbury Phase 2 reuses chain ID 4221 and call for checking the genesis hash and AddressManager, so chain ID alone is insufficient. See the [official network guide](https://github.com/genlayerlabs/genlayer-docs/blob/7c3ad7c4bc738a7c55d05df780dd76c2cb052db6/pages/developers/networks.mdx).

The guide lists Studionet as a stable hosted development environment, not as the production-like testnet. It documents `https://studio.genlayer.com/api`, chain ID 61999, and its Studio explorer. No network endpoint was contacted in this work, so neither Studionet nor Bradbury is selected or identity-verified. In particular, do not substitute a legacy SDK descriptor for the current Phase 2 Bradbury GenLayer RPC without verifying it against the official release information and independent network identity evidence.

## What the different tests establish

- **Ordinary Python/backend tests** validate API/application behavior and fake-client driver/adapter safety: snapshot identity and policy associations, durable transaction ID recording before polling, pending/failed/unknown lifecycle handling, query-only recovery, explicit resume gates, and no implicit second submission. They do not contact GenLayer or establish target runtime compatibility.
- **Direct Mode** executes contract Python in the pinned in-memory testing suite and mocks nondeterministic model responses. It exercises deterministic contract logic and both policy modes. It is not real model accuracy, GenVM/WASM execution, live validator consensus, or a deployed transaction.
- **SDK source/API inspection** establishes what the pinned off-chain Python SDK source declares and exposes. It does not establish which runtime a network executes, remote endpoint identity, contract compilation, or validator behavior.
- **Artifact compilation** must use an authoritative target-supported toolchain and exact immutable runner. No successful compile or execution of this artifact in a selected target GenVM/WASM environment is claimed by this repository's current qualification evidence.
- **Live deployment** is requested in the current work, but must not proceed until a selected target and endpoint are independently authenticated, the exact contract/runtime is shown compatible with that target, an authorized signer is configured securely, and a target-specific fee/funding estimate has been verified and explicitly approved. This offline preflight cannot establish those facts or perform the transaction. Review public calldata/state and procurement confidentiality before any future deployment.

## CI and maintenance

The default CI job runs backend, adapter, preflight, and driver tests. The preflight tests patch network, subprocess, and SDK-driver call paths to fail if touched; they also check secret redaction, missing evidence, mutable and merely digest-shaped runtime references, and removal of the probe option. The GenLayer job installs the repository-pinned environment, parses the JSON report, asserts that local dependency/configuration checks pass while deployment blockers remain, then runs the Direct Mode suite. CI workflow configuration is evidence of intended coverage only; actual job outcomes must be reported separately.

The preflight deliberately does not install or repair dependencies. Use the documented locked setup only when separately authorized as a development-environment action; it is not a deployment qualification step. Keep both procurement policy modes and the application-versus-contract trust boundary unchanged. Evaluation output is an evidence interpretation, not legal advice, procurement eligibility, or an award decision.
